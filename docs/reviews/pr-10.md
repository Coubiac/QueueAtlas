# Revue de la PR #10 — stockage SQLite v1

Revue du 4 octobre 2026, référence initiale
`6b861179f915917aae5f8c7452194e939b93681e`, basée sur main après fusion de #9.
Coordinateur et auditeur agent indépendant en lecture seule, selon le cadrage.
Périmètre : Source/Sink, migration v1, Open et Commit. FileSource, lectures paginées,

## Constats et corrections

1. **P2 — base étrangère migrée** : le contrôle comptait uniquement les tables
   et `LIKE 'sqlite_%'` excluait aussi `sqliteApp` (`_` joker). Une table de ce nom
   ou une vue seule pouvait donc recevoir WAL, tables QueueAtlas et user_version=1.
   Tous les objets utilisateur sont désormais comptés, avec préfixe interne
   littéral `NOT GLOB 'sqlite_*'`, avant WAL et dans la transaction de migration.
   Version négative aussi refusée aux deux étapes, avant mutation persistante.

2. **P2 — horodatage indexé inventé** : UnixNano n'est pas défini hors plage int64.
   Une année RFC5424 9999 valide pouvait donner un instant au XIXe siècle.
   La projection UTC nécessite maintenant un aller-retour exact. Sinon SQL NULL,
   avec date brute, année, zone et qualité conservées ; record et checkpoint
   restent acquittés. Tests des années 0001/9999, bornes int64 et voisins à 1 ns.

3. **Fichiers annexes** : Open contrôlait seulement les droits du fichier principal.
   Un WAL existant peut rester lisible par d'autres utilisateurs. Contrôle Unix
   des sidecars -wal/-shm/-journal avant connexion et refus des fichiers non réguliers
   avant usage. Tests Unix : driver conservant un WAL 0644, refus d'Open, sidecars
   trop ouverts, FIFO et fichiers neufs privés. Ce comportement Unix est à confirmer
   par la CI Linux de la tête publiée avant clôture. Parent protégé toujours requis.

Un contexte déjà annulé ne crée plus de base. Aucun schéma, format d'observation
ou pilote changé. La différence date observée/projection stockable est documentée
dans ADR-004 ; ReadAt/FirstSeen restent des métadonnées produites par les sources.

## Vérifications et garanties relues

Les nouvelles régressions via Open/Commit échouaient sur la référence initiale
(bases étrangères et dates), puis passent avec le patch sous Windows. Vérifications
locales : go test ./..., go vet ./..., git diff --check, builds Linux amd64/arm64
sans CGO, compilation des tests SQLite Linux amd64 sans CGO. Relecture indépendante
du correctif : aucun autre blocage concret identifié ; validations Unix par CI requises.

Requêtes avec valeurs liées, namespaces source/origine et clés étrangères,
idempotence par provenance avec refus de contenu divergent, checkpoint monotone,
rollback de batch et migration, reprise de base v1, FK/trusted_schema/FULL par
connexion et un seul accès physique sont couverts par code et tests. Les doublons
ne remplacent pas l'observation déjà acquittée. Le Sink utilise l'identité configurée
de source, distincte de l'hôte déclaré du journal. Projections M3 non alimentées.

La CI de la tête publiée et la décision de fusion sont consignées dans la
[PR #10](https://github.com/Coubiac/mailtrace/pull/10) et le point de reprise.

## Limites

Audit assisté par agents et tests synthétiques ; pas de certification humaine
externe ni preuve d'absence de toutes les erreurs. Métadonnées filesystem non
atomiques : le propriétaire doit protéger le répertoire. ACL Windows non validées
par les contrôles Unix. Sources internes responsables des instants ReadAt/FirstSeen
et des checkpoints correspondant aux octets réellement consommés. Pas de borne
de batch globale destinée à une API publique : les appelants sont internes.

Mesures de charge, taille du binaire, inventaire des licences transitives, sauvegarde
et rétention opérationnelles restent requis avant distribution. WAL sur réseau
exclu. Aucun paquet installable ou endpoint public n'est livré par cette PR.
